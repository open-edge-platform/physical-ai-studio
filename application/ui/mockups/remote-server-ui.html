The three credential failure states

Each one names the exact recovery command instead of a generic “connection failed”. Because Studio holds no credentials, every fix is something the user performs in their own SSH setup — never a field they retype here.
✕
Host fingerprint not accepted (blocks save): the host key for gpu-01.lab.internal is not in ~/.ssh/known_hosts. Run ssh gpu-01 once to accept its fingerprint, then retry. Studio will not connect to an unverified host, and it will not add the key for you.
✕
SSH host alias not found (blocks save): there is no Host old-rig entry in ~/.ssh/config any more. Pick a different alias above, or re-add the entry and reload. This is the drift case — the saved alias is the only thing in the database, so a renamed config entry surfaces here rather than at job time.
✕
Key needs a passphrase and no agent is available (blocks save): ~/.ssh/id_gpu01 is passphrase-protected and SSH_AUTH_SOCK is not set. Run ssh-add ~/.ssh/id_gpu01 to load it into your agent, then retry. Studio has no passphrase prompt by design — adding one would mean holding the secret.
